# AI 训练 MAA 经验库

## 文档定位

本文用于记录训练、调优和验证 MAA 运行逻辑时得到的经验与结论，服务对象包括后续拉取仓库的人、维护者和继续参与分析的 AI。这里记录可复用的方法、证据链、已验证结论和已知边界，不替代具体功能的设计文档、代码注释或用户手册。

文档可以覆盖所有模式。当前示例来自集成战略｢黑流树海｣，今后卫戍协议、基建、保全派驻等模式应沿用相同结构追加，避免把经验散落在单次日志或聊天记录中。

## 放置位置与命名

主文档放在 `docs/zh-cn/develop/ai-training-experience.md`，其他语言放在对应的 `docs/<locale>/develop/ai-training-experience.md`。文件名使用稳定的英文 slug，便于跨语言链接、GitHub 搜索和后续拉取；标题按语言翻译。新增文档必须同步五种语言的 frontmatter 和核心结构。

更新时保留已有条目，不重写成只描述最终代码的说明。一个经验条目应能让后来的人回答：当时看到了什么、怎样证明根因、改了什么、验证到什么范围、还缺什么证据。

## 长期维护结构

每个条目建议使用下面的字段：

| 字段 | 应记录的内容 |
|---|---|
| 日期与模式 | 发现或验证日期、主题、难度、客户端、分队和账号条件 |
| 目标 | 想提升的行为和成功判据 |
| 现象 | 用户反馈、日志、截图、识别分数、失败阶段 |
| 证据 | 截图、原始日志、Core 评估、关卡数据、官方或 Wiki 链接 |
| 根因假设 | 候选原因及排除过程，区分事实和推断 |
| 改动 | 文件、配置、代码、资源和备份位置；说明为何这样改 |
| 验证 | 离线测试、构建、资源加载、单关卡实机和完整长跑结果 |
| 结论 | 已证实、部分证实、未证实或推翻 |
| 后续 | 需要补的样本、回归范围、风险和回滚方式 |

建议按主题维护索引：识别与视觉、流程与恢复、招募与经济、战斗与关卡、路线与事件、账号与模组、工具与数据来源。一个条目只记录一个主要问题；跨主题问题用链接互相引用。

## 记录示例：招募模板版本过旧

**现象：**新客户端进入肉鸽招募页后，`Recruit` 模板长期匹配不到，流程在招募页面重试到上限。截图显示页面整体布局发生变化，旧模板还包含旧版背景装饰。

**排查：**先保存原始截图和 Core 日志，再用 `tools/maa_core_eval.py` 对旧模板做离线匹配。分别检查模板版本、客户端类型、缩放、阈值和 ROI；不要因为一次低分就直接扩大阈值。若新旧页面的按钮位置和背景都变了，应判断为资源版本问题；若模板局部仍吻合而目标被裁掉，才判断为 ROI 问题。

**修复记录应包含：**原模板备份路径、干净截图来源、裁剪区域、匹配阈值、修改的任务名、是否同步国际服资源，以及新旧截图的分数对比。新模板只保留稳定的游戏 UI 特征，避免把直播皮套、鼠标、弹窗或动态背景写入模板。

**验证：**离线用旧失败截图和新截图分别评估；Debug Core 资源加载；再在真实招募页验证至少一次完整的识别、选人、确认和返回流程。单张截图命中只能说明模板可用，不能说明跨分辨率和跨客户端稳定。

## 记录示例：搜索区域宽度不足

**现象：**OCR 或多卡位识别只得到左侧干员，右侧卡片始终缺失；日志中的单卡识别分数正常，但列表总数少于截图可见数量。

**排查：**保存完整页面截图，标出任务 ROI 的四条边，再对照当前页面中最右侧卡片、横向滚动区域和缩放后的坐标。先确认目标是否在 ROI 外，再检查裁剪后是否被降采样、遮罩或其他模板覆盖。扩大 ROI 时同时检查误识别、重复卡位和性能，不能只把宽度改成全屏。

**修复记录应包含：**旧 ROI、新 ROI、截图分辨率、列表卡片数量、OCR 原文、去重规则和边界样本。若页面会横向滚动，应记录滚动前后使用的同一帧或明确的分页状态，避免把不同时间的卡片拼成一组。

**验证：**至少使用左边界、右边界、空列表、满列表、临时干员标记和低分 OCR 样本；确认扩大区域后不会把旁边按钮或下一页卡片误算进当前列表。

## 当前黑流树海训练经验

### 2026-11-06 动态路线规划与地图 OCR

- BlackFlow 路线按状态持续重规划：进入节点、消耗加工品、随机传送、地图补全或行动力变化后，都以最新状态重新计算。
- 状态保留当前位置、行动力、加工品次数、本层失效标记、已消费羽瞰点、已完成节点、地图版本和动态步数成本。羽瞰点进入时一次性返还行动力，净消耗可以为零，但不免除加工品次数。
- 小八界等随机传送保留所有可能落点；安全性按最差落点验证，奖励按保证收益排序，确认实际落点后立即重规划。
- `strategy.json` 新增非空奖励节点密度目标，并按 `candidate.boss` 在所有险路恶敌层保留剩余行动力；普通层不套用出口丢弃规则。
- 第五层 OCR ROI 已扩展到 `[79,95,1061,504]`，同一官号截图的新旧配置均得到 5×10、44 节点、46 边且 JSON 逐字段一致。

### 招募模板和搜索区域

- 招募模板版本过旧时，先比较干净截图、客户端类型和模板分数；不要把阈值调低当作修复。
- 招募卡片 ROI 宽度不足会造成右侧卡片永久缺失。扩大区域后必须检查分页、误识别、重复卡片、临时招募标记和 OCR 的边界样本。
- 当前黑流招募策略已加入“没有医疗干员时提高医疗候选优先级”，但这只在候选列表实际出现医疗干员时生效；一次没有医疗候选的失败不能被描述为“医疗优先级代码失效”。

### 未确认部署地块和巨蕈

- `BattleHelper` 在部署证据为 `Unknown` 时记录并隔离地块，防止不同干员重复点击同一疑似不可用位置；确认成功后解除，战斗重置时清空。
- 该修复在 B 服｢木本玉米｣中实际出现过两个被隔离地块，战斗仍出现 `RoguelikeCombatEnd`。这证明隔离逻辑有效，但不证明所有地图的落点都正确。
- ｢无主地｣的巨蕈不是普通远程位：必须由｢罗德岛临时雇员｣清理后才变成可部署远程位。专用作业 `autopilot/无主地.json` 已按击杀阶段分成两次清理，坐标和资源加载通过，但至今尚未取得该作业的正向实机覆盖。

曲折密道的运行时类型为 `door`，不是 `portal`（后者对应｢误入奇境｣）。现有模型在同层恰有两个相容密道节点时建立双向配对，规划器将入口转换为配对端落点。调试时应对照入口目标、实际落点和走到入口的费用，不能仅搜索英文 portal 后断言传送未实现。用户截图补充的机制是入口间传送不额外扣步数，仍需实机核对移动事务。

- 另一局进入第三层｢光荣远征｣后在技能处理和页面恢复阶段结束。若日志停在 `click_skill`、`RecoveryFailed` 或结算页，先确认模拟器截图和 Core 进程状态，再决定是页面恢复、技能检测还是战斗本身的问题。

### 路线、事件和完成判据

用户于 2026-11-01 提供的首层截图对应 `map_templates.json` 中的 `floor-1-horizontal-fork`。模板按零基行列坐标标出右上 `(0,4)`、右下 `(2,4)` 两个出口；用户进一步确认当前小人所在的中右 `(1,3)` 固定为诡意行商，其他普通节点可能变化。本轮 `blackflow_round3_20261101` 日志已匹配该模板并从右上出口进入第二层，但尚未实测经右下出口离层。当前模板实现只补出口，固定商店尚未作为模板事实接入运行时。

出口推断必须保留用户补充的前提：在首层外围的单连线末端中，先排除已识别作战和｢未知的凶戾｣，再结合两个出口及末端战斗节点的结构判断其余出口。不能把外围战斗误判成出口，也不能将这一规则外推至其他楼层或不匹配的拓扑。推断出口与画面确认出口分别记账；遇到新拓扑保存全图、连线和节点类别，展示给用户复核。对这类图，途经｢得偿所愿｣的规划应检查其后通往右下出口的真实连线路径和行动力，而非只规划已揭示的右上出口。

- 保密等级 16 下｢险路尽头｣不再提供加工品，不能把出口当成加工品补给；商店刷新价格也会上升。路线策略必须分别维护行动力、加工品和源石锭。
- 新增风险规则会默认绕行没有专用作业的｢原始娱乐｣和｢掠夺成性｣，因为调查记录显示它们会进入特殊战斗。规则测试已从 4 个风险名称更新为 6 个，42 项回归通过。
- 目前最远的 B 服实机证据是进入第三层并完成部分第三层战斗，未出现 `game_pass:true`。只有最终结算明确出现该字段，才能登记为一局第一结局通关；随后还要用同一账号和分队做多局随机回归。

### 已知结局事件标记和召唤物能力

- 不期而遇节点右上角的小人图标是已知的结局相关标记。它不是普通随机不期而遇；当前策略中的 `marker_type=informant`、`candidate.badged` 和 `ending2_informant` 应按固定二结局页面处理，并记录标记截图与页面跳转结果。

### 2026-11-02 新增机制记录：密道、特殊层增益与首领防线

- **曲折密道按传送门处理**：用户补充确认两枚曲折密道互相连通，走到其中一枚后自动传送到另一枚；行动力只扣走到入口节点的步数，不再额外扣传送后的步数。实现和复盘时要把它记成一条“入口边 + 零费用落点”的移动事务，不能把传送端再计入最短路费用。当前运行时已经以 `door` 配对并解析另一端落点，下一次日志需同时保存入口坐标、配对端坐标、移动前后行动力，验证是否确实只扣一次。
- **特殊层增益要记录触发和持久态**：进入下一层时会出现“触发了·激活‘微型胶囊’”的过场提示；进入该层地图后，顶栏会保留对应的黑色星芒图标（用户截图示例为“血色空脉”）。训练数据应拆成 `entry_prompt`（触发提示）和 `layer_badge`（层内持续图标），两者都识别到才算完成一次增益同步。截图只证明 UI 现象，增益具体数值仍需从关卡数据或战斗前后对照实验确认，不能凭图标名称推断效果。
- **隐匿草地与炮台**：绿色草地会隐藏身形，远程小炮不会攻击处于隐匿状态的干员；只有该干员阻挡敌人后才会被炮击。落点评分因此继续提高 `tile_grass`，但不能把草地当作绝对安全区：阻挡位、全图隐匿和炮台的特殊索敌会使条件失效。
- **首领战防线**：用户实机观察到第三层首领会周期性穿过一名阻挡干员，并会施加全图隐匿；需要准备两名可替换的阻挡干员，避免单阻挡被穿过后蓝门失守。该首领地图四角存在远程炮手，作业应在核心输出稳定后优先清理角落炮手，再处理首领本体。`光荣远征.json` 当前已放置两路阻挡，但尚未有 `game_pass:true` 证据；后续验证必须分别记录“双阻挡同时在场”“四角炮手清除时间”和“首领穿过阻挡后的补位”三个事件。

## Wiki 与外部资料的扩展搜索方法

不要只引用用户最初给出的页面。先从主题页的目录和页内链接扩展到：调查记录、不期而遇事件、全部关卡记录、敌方图鉴、非常规敌方图鉴、装置条目、敌人详情、分队与难度页面。再把外部资料和游戏数据、当前资源文件、实机截图交叉核对。

主题页目录本身是导航索引，应按需要逐节读取：保密难度、调查者增益、开局与指挥等级、分队、区域、地图与移动、节点类型、零件与零件箱、理想域、关卡记录、调查记录、生命游戏、黑流数据库、结局、零件目录和蚀刻章。需要关卡玩法时直接进入｢关卡记录｣，需要事件选项时进入｢调查记录（事件）｣，需要敌方机制时再沿敌方图鉴或具体敌人链接继续展开。

PRTS 可以作为互补来源：[黑流树海主题页](https://prts.wiki/w/%E6%B2%89%E6%B2%A6%E8%80%85%E7%9A%84%E9%BB%91%E6%B5%81%E6%A0%91%E6%B5%B7) 的目录把独特机制、活动道具、开始探索、区域、事件节点、结局和关卡一览分开，并补充移动限制、追猎、加工品、零件箱、理想域、恶笼草、应急雇佣和难度叠加规则。使用时以 BWIKI 的事件与关卡记录补充选项，以 PRTS 的机制与数值描述交叉核对，最后以游戏原始数据和实机截图确认当前版本是否一致。

例如，[敌方图鉴](https://wiki.biligame.com/arknights/%E6%95%8C%E6%96%B9%E5%9B%BE%E9%89%B4)说明可按名称、关卡代号、敌方编号和地位／种族／攻击方式／伤害类型／位置筛选，并提醒存在未收录于常规敌方图鉴的单位；这类页面适合发现搜索入口，具体数值仍要记录来源版本和适用模式。Wiki 的关卡页可提供固定地块、装置和敌方情报，不能直接推断随机敌人配置在所有常规战斗中都相同。

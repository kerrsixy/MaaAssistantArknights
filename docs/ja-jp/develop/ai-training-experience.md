# MAA の AI トレーニング経験

この文書は、MAA の学習、調整、検証で得た再利用可能な経験と結論を記録します。後からリポジトリを取得する開発者や、作業を引き継ぐ AI が利用します。現在の例は統合戦略 ｢沈む者の黒流樹海｣ ですが、今後は保全派駐など別モードも同じ形式で追加します。

各項目には日付、モード、クライアント、目標、現象、証拠、仮説と除外、変更、検証範囲、結論、次の作業を記録してください。スクリーンショット、原ログ、Core 評価、データスナップショット、外部 URL と取得日を残し、事実と推測を分けます。

## 例

### 古い募集テンプレート

募集画面で `Recruit.png` が一致しなくなった場合、失敗画像とログを保存し、`tools/maa_core_eval.py` でテンプレートの世代、ROI、閾値、倍率、クライアント資源を切り分けます。新しいテンプレートはゲーム UI の清潔な画像から作り、バックアップを残し、認識から確認・復帰までを Debug と実機で検証します。

### 検索 ROI の幅不足

OCR が左側のカードだけを読む場合、全体画像、旧新 ROI、カード数、OCR 結果、重複除去規則、境界ケースを記録します。ROI を広げた後は誤認識、ページング、縮小、性能を確認します。

## 現在の黒流樹海の実経験

- Bilibili 版では接続前に `ClientType=Bilibili` を設定し、黒流樹海のターミナル画面から開始します。デスクトップ、ログイン、前回の結果、分隊選択画面は先に記録して整理します。
- 6 名の新オペレーター、アバター、`dispatcher` 分岐を同期しました。Horn の目標点配置は実戦中のモジュール装備証拠が必要です。
- Unknown の配置マスは `BattleHelper` が隔離します。Bilibili の｢木本玉米｣で再クリック防止を確認しましたが、全マスの正しさを保証するものではありません。
- ｢無主地｣の巨大キノコは一時雇用員で清掃してから遠隔マスになります。専用作業は作成済みですが、実機の正例は未取得です。
- 敵構成はランダムなので固定作業だけでは安定性を証明できません。第三層｢生存習性｣は医療不足と青門側への偏った配置で 3/22 に失敗し、右側作業を実機検証中です。
- `game_pass:true` の最終結果だけを第一結局の通過として記録します。

## 情報源の拡張

テーマページから調査記録、ステージ記録、敵図鑑、非通常敵図鑑、装置ページ、個別の敵ページへ辿り、Wiki の内容をゲームデータ、リポジトリ資源、実機画像と照合します。敵図鑑は名称、ステージコード、ID、地位、種族、攻撃方式、ダメージ種別、位置で検索できます。各結論には URL と取得日を付けます。
